# 题库数据化与刷题网站设计

## 结论

采用 JSON 作为题库维护与导入格式，PostgreSQL 作为网站运行数据库。原始 PDF 保留，图片和表格资产独立存放。题库内容以版本化 JSON 为维护源，数据库通过发布流程更新；用户答题、复习和进度只写数据库。不同时在两个地方人工修改题目。

## 已核实的来源特点

目录共 47 份 PDF：经济基础真题速攻 10 份、金融真题速攻 4 份、经济基础高频错题 18 份、金融高频错题 15 份。

代表性样本检查发现：
- 真题速攻：`1. 【单选题】`等题头，后部通过`1. 正确答案：B | 解析：…`关联答案。
- 高频错题：存在逐题附`【答案】`与`【解析】`的版式；经济基础样本按章节重新编号；金融样本存在`【12-单选题】`题头。
- 案例题：材料可能包含表格；金融案例样本第一页的资产负债表在普通文本提取中遗漏，需抽取表格或保留图片。
- “案例分析题”只表示材料组织形式，不能作为单选/多选判定依据；金融案例第 37 题答案为 A,D。
- 存在跨页、水印字符混入、页眉页脚与宣传页；公式的文本阅读顺序可能错乱。

已对全部 47 份 PDF、共 877 页完成基础文字提取，各文件均有可提取文字；原始提取结果位于 tmp/pdfs，尚未清洗。以上是基础提取与代表性页面检查，不能视为全部题目已经完成解析、配对或校验。不得根据文本提取结果直接统计已上线题数。

## 数据分层

1. 原始层：PDF 文件、SHA-256、来源路径与稳定 source_id。
2. 提取层：逐页文字、坐标、原始题号、章节、题目页和答案页、提取告警。
3. 维护层：经过校验的结构化 JSON 与 assets；纳入版本管理。
4. 运行层：数据库题目版本、课程结构、用户答题及复习状态。

JSON 适合审阅差异、脚本维护和重新导入；用户并发写入、关联查询、事务和进度统计由数据库承担。无需为 MVP 引入额外文档数据库或搜索服务。

## 题目格式

每题一个稳定 question_id（UUID），修订生成独立 revision_id。题号仅是来源信息。不能使用数组下标、文件名或题干哈希作为永久 ID。文件改名和题目修订仍保留稳定 ID；哈希用于检测重复和内容变化。

建议按来源维护 JSON 文件，每份包含 schema_version、source_id、questions。单题示意结构如下；内容为格式示意，不对应原题：

```json
{
  "question_id": "<稳定 UUID>",
  "revision_id": "<本次修订 UUID>",
  "revision": 1,
  "subject": "finance",
  "response_type": "multiple_choice",
  "material_id": null,
  "stem": [{"type": "text", "text": "示例题干"}],
  "options": [
    {"id": "A", "content": [{"type": "text", "text": "选项一"}]},
    {"id": "B", "content": [{"type": "text", "text": "选项二"}]}
  ],
  "answer": {"option_ids": ["A", "B"]},
  "explanation": [{"type": "text", "text": "示例解析"}],
  "knowledge_point_ids": [],
  "status": "draft",
  "source_refs": [{
    "source_id": "<稳定来源 UUID>",
    "section": "章节标识",
    "local_number": "1",
    "occurrence": 1,
    "question_pages": [2],
    "answer_pages": [3]
  }]
}
```

约定：页码使用 PDF 中从 1 开始的物理页序。支持 text、math（LaTeX）、image、table 内容块；图片包含路径和替代文字，表格可用结构化单元格表达。复杂公式、表格若暂无法可靠转换，使用经核对的局部截图并标记待优化。案例材料独立保存，多个小题引用同一 material_id；每个小题仍有独立 response_type 和答案。

保留 stable option id；前端打乱显示顺序也按 ID 提交。单选答案只能一个，多选答案多个；案例标签不参与判分。评分规则以独立、版本化 scoring_policy 保存，练习模式先采用完全匹配；模拟考试若需要部分得分另行配置。

## 最小数据库模型

| 表 | 用途 |
| --- | --- |
| subjects / knowledge_points | 科目、章节、知识点层级 |
| sources / source_versions | 稳定来源、PDF 内容哈希及文件版本 |
| materials / material_revisions | 案例公共材料及不可变版本 |
| questions | 稳定题目 ID、当前版本、启停状态 |
| question_revisions | 不可变题目版本，内容块和选项用 JSONB，答案与解析为服务端字段 |
| question_source_refs | 题目版本与来源版本、章节、题号、页码的关联 |
| question_knowledge_points | 题目与知识点多对多关联 |
| courses / units / lessons / lesson_questions | 学习路径、短课及题目排序 |
| users / practice_sessions / session_items | 用户、练习会话、会话选题及版本快照 |
| attempts | 每次提交、选项、用时、得分、评分规则版本；关联实际作答的 revision_id |
| user_question_state | 掌握度、最近作答、下次复习时间，可由答题记录重建 |
| user_daily_activity | 按用户时区计算日目标、连续学习天数 |
| import_batches / releases | 导入校验、差异报告、发布及回滚记录 |

科目、状态、用户 ID、到期时间等常用查询字段用普通列；题干/选项等多样化内容用 JSONB，避免所有数据塞进一个 JSONB 字段。图片文件不写入 JSONB。历史答题必须关联旧版本；新版答案不能改变旧答题结果。实质改变题意时应新建题目，而不是继承原掌握度。

## PDF 导入与维护

流程：扫描 → 按来源版式提取 → 候选题目及材料 → 校验报告 → 人工修订 JSON → 导入预览 → 事务发布。

- 两类版式使用独立解析器。先按页、坐标与字体清理页眉水印，不能简单删除所有单字或数字行，避免误删公式与选项内容。
- 集中答案版按文档、章节、题号、出现次序配对；逐题答案版使用题目边界解析。仅靠题号做全库关联会串题。
- 题干、选项、答案、解析及材料都保留页码范围；跨页连续拼接。
- 校验缺答案、孤立答案、题号重复、答案选项不存在、单选多答案、空题干、材料缺失、资源路径、异常字符及公式表格。
- 初次抽取题目全部进入待审状态。自动校验通过不等同于内容正确；含材料、公式、表格或配对歧义者必须核对原页。
- 同源相同文件哈希跳过；改版生成 source_version；导入须幂等。来源题目匹配有歧义时进入人工映射，不能静默覆盖。
- 内容相似度产生疑似重复报告；相似不代表同题，尤其注意“正确/错误”“属于/不属于”以及年度口径差异。确认同题后可关联多个来源。
- 发布前输出新增、修订、停用、告警清单；存在阻断错误不发布。源文件少了一题不自动删除线上题，显式停用。
- 发布切换当前版本并保持旧版本可访问；回滚只回退题库发布，不回滚用户答题记录。

后端维护可提供命令接口：`bank extract`、`bank validate`、`bank diff`、`bank publish`、`bank rollback`。这些目前是设计接口，尚未实现。首次实施先选单选、多选、案例、两类高频各一份验证完整流程，再扩展全库。

## 类多邻国体验

题库分类不直接等同于课程。课程以知识点组织，来源目录和期数作为筛选信息。MVP 每节约 5–10 题、3–5 分钟，提供路径解锁、即时反馈、错题复习、经验值、每日目标与连续学习记录。先验证学习闭环，再考虑排行榜等功能。

每次答题后服务端判分，返回本题答案、解析和奖励；答错与不熟悉题进入复习队列，后续通过间隔复习重新出现。初期用可配置的简单间隔规则，积累数据后再评估更复杂调度。到期复习优先，搭配少量新题；同一会话避免重复塞入相同题。会话固定题目和材料版本，保证更新时进行中的练习可完成。

最小 API：
- GET /courses：课程路径和用户进度。
- POST /practice-sessions：按课程或复习队列创建练习。
- GET /practice-sessions/{id}/next：返回题干、选项和必要材料。
- POST /practice-sessions/{id}/answers：按 session_item_id 提交选项和幂等键，服务端返回结果。
- GET /practice-sessions/{id}/summary：本节学习结果。
- GET /me/reviews：待复习数量及概要。

提交前的响应不得包含答案、解析或可推导答案的内部字段；后端明确选择响应字段，不能直接序列化数据库整行。提交需校验题目属于当前用户会话；答题记录、进度和奖励在同一事务中更新，重复提交不重复发奖。

## 实施顺序

1. 建立题库格式、来源清单和样本导入工具，输出可人工复核的题目与问题报告。
2. 完成全库提取、校验和人工复核，发布第一版题库。
3. 建数据库与独立后端，先完成创建练习、答题、判分和复习 API。
4. 前端接入短课、路径、即时反馈和日目标。
5. 后续通过 JSON 和后端命令维护题库，不需要先做上传页面。

当前未创建网站、数据库或已验证的正式题库。本文件用于明确设计与后续实现边界。
