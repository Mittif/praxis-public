# Praxis 架构与数据约定

Praxis 是共用 API 的双界面应用。主站负责较完整的阅读和反馈体验，简洁模式提供独立的轻量页面；两者复用同一账号、题库和判分规则。

## 部署单元

| 单元 | 入口与职责 | 持久化 |
| --- | --- | --- |
| `web` | Caddy 提供主站和 `/simple/`，转发 `/api/` 与 `/assets-bank/` | HTTPS 证书卷 |
| `app` | FastAPI 校验身份、选题、判分、读取材料和投影统计 | 通过数据库连接保存用户状态 |
| `db` | PostgreSQL，默认不映射宿主端口 | `praxis_database` 数据卷 |

前端是 Vite 多入口构建：`frontend/src/` 使用 React，`frontend/simple/` 使用原生 JavaScript。两者通过 `frontend/shared/presentation.js` 共用显示字母、解析引用和分页计算。主站使用 TanStack Query 缓存查询结果；同源页面通过 BroadcastChannel 通知更新，窗口重新获得焦点时读取服务端状态。跨设备同步依赖后续请求，不使用 WebSocket 推送。

题库 JSON 与材料图片保存在本地运行目录，在构建应用镜像时按允许列表复制。进程启动后载入题库，修改题库需重新加载服务。它们不与用户数据库混合分发，也不随公开源码仓库提供。

## 数据模型

| 数据 | 作用 |
| --- | --- |
| `accounts` | 用户名、scrypt 密码摘要与角色 |
| `auth_sessions` | 登录令牌的 SHA-256 摘要、账号与有效期 |
| `practice_sessions` | 账号归属、本轮题目快照、结果、进度与乐观版本号 |
| `answer_events` | 每次有效提交的题目、结果和服务端时间 |
| `question_bookmarks` | 当前账号收藏的题目 ID |

一次练习将完整题目快照保存在会话 JSON 中，便于保持题库更新前的内容与顺序。答题事件用于计算累计次数、错误次数和连续正确次数。该实现易于自托管与恢复，但大题库和大量历史会话会增加读取与聚合开销；后续可拆分索引表、预聚合统计及服务端分页。

## 创建、作答和恢复

1. 客户端提交练习范围，API 校验账号和参数，从规范题库选择题目。
2. API 深复制题目，记录原始标签并确定本轮顺序；有顺序依赖或解析引用不明确的题目保持原序。
3. 作答前的会话接口不返回答案、解析或解析引用片段。用户提交固定选项 ID，由服务端快照判分。
4. 结果、会话版本更新与答题事件在事务内提交。同一会话索引使用同一个事件标识，重复提交复用原结果。
5. 主站顺序推进；简洁模式可乱序提交，主站共享进度始终指向首个尚未完成的位置。
6. 自动续接简洁模式会话要求题目范围与题库版本均匹配。通过历史会话 ID 显式恢复时，读取旧快照，不替换成当前题库。

错题连续答对两次后移入已巩固，原有错误事件保留。错题本回看从当前账号的最近作答快照读取内容；两站使用相同选项 ID，展示顺序不同也不会改变判分身份。

## 显示字母与解析

`option.id` 是稳定身份，`source_label` 表示原题字母，`label` 表示本轮字母。服务端将明确的解析引用编译成绑定 ID 的片段；浏览器根据实际显示顺序生成字母。`explanation` 字段继续保留原解析。

原文可以从文本片段与 `source_text` 无损重建。缺失来源标签、无法确认用途的字母或不完整片段会回退原文；不使用运行时模型猜测。详见 [解析引用规则](explanation-references.md)。

## 身份与内容边界

- 登录使用 HttpOnly、SameSite Cookie；生产环境配置 Secure。服务端只保存令牌摘要，修改密码会撤销已有登录会话。
- 会话、答题记录和收藏按账号查询。状态修改请求检查 Origin 与跨站请求标记，密码校验错误不回显请求体。
- 题目 API 与材料图片均要求登录，响应使用 `Cache-Control: no-store`。查看答案是显式的授权操作，不计入作答统计。
- 个人配置、数据库、备份、题库和密钥不进入公开包；Docker 构建上下文使用允许列表。
- 登录频率限制是单进程内存实现，适用于当前规模。多副本部署需要统一限流和可信代理配置，并进行额外容量与安全验证。

## 数据演进

数据库结构通过 Alembic 升级。题目维护使用固定 ID 和修订号；换行整理只改空白字符，备份后替换文件。更新前备份数据库与题库，应用回滚保留旧镜像；数据库恢复属于单独、明确的运维操作，不能用删除卷来替代。
